# Eval corpora — `.eval.jsonl` trigger sets and `.cq.md` competency questions (any optimization target)

## Trigger evals — `<skill-id>.eval.jsonl`
One append-only file per optimization target: `<skill-id>.eval.jsonl`; each line is one JSON object recording a skill-optimizer Pass H trigger query and verdict: `{"date", "query", "expect" ("trigger"|"skip"), "verdict", "description_version", "description_sha256"}`.
Subsequent runs replay the stored set FIRST (true regression: did the new description break previously-passing queries?), then append fresh queries — this makes the 60/40 train/validation split enforceable across runs.
When a run intentionally changes the skill's scope, re-label affected rows with `{"retired": "<YYYY-MM-DD>", "reason": "..."}` instead of counting their failures as regressions.
Verdicts are same-model trigger predictions, not harness-observed activations — the fixed query set makes before/after comparable, not objective.
Seeded rows (converted from a skill's prose Should/Should-NOT-trigger examples or curated collision sets) carry `null` for `verdict`, `description_version`, and `description_sha256` — verdicts are run predictions, never fabricated at seed time; the first Pass H replay fills them against the then-current description. A row's `note` field may record routing rationale or replay-sequencing constraints.
Skills generated by `/dr` inherit this convention from day one: the mandated skill-optimizer run in /dr Phase 2 step 4 persists its Pass H queries and verdicts to `<skill-id>.eval.jsonl` here (sko Pass H replays any persisted corpus first, then appends).

## Competency-question corpora — `<family>.cq.md`
Second artifact type: one markdown file per concept family, `<family>.cq.md`, holding 5–10 competency questions — "someone working <subject> should be able to ask X and reach a skill" — one bullet per question.
Consumers: concept-family-explorer writes the corpus when framing a family (Step 1) and its coverage-saturation check requires every CQ to resolve to a HAVE/researched node (Step 8); skill-tree-architect replays the corpus as scored routing probes (Phase 4), appending probe outcomes as rows here, and when no `.cq.md` exists for a touched family it persists its own invented probes as that family's seed corpus.
Severity, exit conditions, and the loop these evals gate: `../convergence-and-severity.md`.
