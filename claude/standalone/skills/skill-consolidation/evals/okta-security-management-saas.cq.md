# Competency questions — okta-security-management-saas

Family seeded by concept-family-explorer, 2026-06-11. Someone working Okta security
management SaaS should be able to ask each question below and reach a skill.

- How should a customer harden the Okta admin console and super-admin accounts against takeover (session binding, admin MFA, HealthInsight)?
- Which Okta phishing-resistant authentication options (FastPass, passkeys/WebAuthn, Okta Verify) fit which user populations, and what does a rollout plan look like?
- How do I design Okta Identity Governance (OIG) access certifications, access requests, and separation-of-duties for SOX/SOC2 access reviews?
- How do I detect and respond to identity threats in Okta System Log events (session hijacking, MFA fatigue, token theft, impossible travel) — the ITDR loop?
- How should non-human identities (service accounts, API tokens, workload/machine identities) authenticating through Okta be inventoried and secured?
- How do I secure AI agents' access to SaaS applications via Okta (Cross App Access, Auth for GenAI, MCP/agent authorization)?
- What does Okta Privileged Access cover versus a dedicated PAM, and when does an account need both?
- How do SCIM lifecycle provisioning and deprovisioning flows prevent orphaned access, and how do I audit them?
- How does Okta fit a Zero Trust architecture — device trust/posture, continuous access evaluation, Shared Signals Framework/CAEP?
- How do I evaluate Okta against Microsoft Entra ID or Ping Identity for workforce identity, and what are the migration trade-offs?
