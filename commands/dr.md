4. **Warm-start from the hub URL library first:** `tam_recommend_urls(query: '<concept>', limit: 10)` per major concept plus one `tam_search_urls(query: '<topic-slug>')`; hits tagged `verified:` within 90 days skip credibility re-grading and join the deep-read list — but MUST still be fetched this run to be cited, and never count toward the per-concept independent-source minimum or the saturation check (every concept still gets fresh discovery searches, including the ~20% negation allocation). Tam MCP unavailable → skip warm-start and the Phase 5 URL save silently; never block the run. Then execute the default retrieval pipeline: 1. Perform a broad web lookup (via `exa` MCP or built-in `WebSearch`). Use standard high-value domain anchors as mandatory starting points (e.g., Wikipedia for general conceptual mapping, GitHub 'Awesome' lists / IETF RFCs for technical standards, arXiv/PubMed for academic topics, CNCF/Cloud Architecture centers for enterprise). These anchors establish baseline context but MUST NOT be the only sources; expand immediately to primary authoritative sites discovered in their references. 2. Extract page text using `web-text-mirror --max-depth 1`. 3. To prevent rate-limiting on large sets, process top concepts live and fall back to local offline corpus. 4. Maintain a highly detailed forensic trace of all actions in `~/.research/forensic_log.md`. Do NOT call any `firecrawl-*` tool — firecrawl is not available in this environment. Gather 3+ **independent** sources per concept — collapse citation chains to one evidentiary point and weight by the credibility hierarchy, both per `deep-research-methods` §Source Evaluation. Run the search→read→infer loop (iterate queries as the concept map sharpens), with ~20% of queries on negation per §Query Formulation; vary terminology across ecosystems.
5. Synthesize into the Context File Template (Overview, Core Concepts, Tools/Frameworks, Methodology, Practical Patterns, Anti-Patterns, Troubleshooting, References). **Synthesis is deterministic** — assert only what the cited sources support; never extrapolate, infer version numbers, or fill gaps with plausible detail. Apply **per-claim confidence:** 3+ independent sources agree → state as fact; 2 → qualify; single-source/contested → flag tentative and preserve the contradiction. Anchor every load-bearing or volatile claim with an inline `[^n]` footnote mapped to its numbered `## References` entry; stamp volatile claims (versions, vendor landscape, pricing, "current state of") `verified-as-of: <YYYY-MM-DD>` — one header-level stamp preferred; a stamp advances only after an actual re-fetch this run, never a date-bump; un-reverifiable → BLOCKED/operator-action row. **Write each concept's synthesis to the on-disk draft immediately as it completes, then update the draft's own `dr:progress` marker — content to disk first, marker second, never the reverse** (full mechanics: canonical § Draft file mechanics). 6. Stop when saturation is reached (2 consecutive searches yield nothing new AND every concept has met the 3-independent-source floor) or at the 15-concept cap (the cap is per topic). Distinguish true convergence from oscillation/thrash (re-querying that returns no NEW evidence) per `iterative-self-refinement-loops` — thrash is its own stop signal, not just a zero-new count. On reaching saturation, flip the draft's `dr:progress` `state` from `"researching"` to `"research-complete"` — still a draft; Phase 2 finalization (optimizer, verification, persist) has not run yet.

### Draft file mechanics (applies throughout Phase 1; full text: canonical § Draft file mechanics)
The generated context file is written incrementally, not assembled in memory and flushed once at Phase 2 — the file itself is the run's live status and its own resume checkpoint.
- **Skeleton first.** At the path resolved in Phase 0 step 7, before researching anything: write frontmatter with a placeholder `description` ("DRAFT — research in progress; not yet trigger-quality") and `version: 0.0.0-draft`; a visible one-line banner under the H1 (`> **DRAFT — research in progress.** 0/<N> concepts complete. Last updated: <ISO timestamp>.`); every Context File Template heading present but empty (`_(pending)_`); and one single-line machine-readable comment: `<!-- dr:progress {"skillId":"<id>","state":"researching","conceptsTotal":<N>,"conceptsDone":[],"conceptsPending":[...],"startedAt":"<ISO>","updatedAt":"<ISO>"} -->`. Keep it single-line, valid JSON — it's what both a human `grep` and the Phase 0 step 7 resume check parse.
- **Per-concept footnotes are append-tolerant.** Scope each concept's citations as `[^<concept-slug>-1]`, `[^<concept-slug>-2]`, … under a `### <Concept>` subgroup in `## References` — never one global running counter, so a later concept's footnotes never force renumbering an earlier one.
- **Asymmetric "usable mid-research."** A **standalone** draft is technically loadable as a skill the instant its `SKILL.md` exists — but its placeholder description is deliberately non-trigger-quality, so don't rely on it firing correctly before finalize. A **hub-spoke** draft isn't discoverable through the hub's routing table or TRIGGER until Phase 2 wires it in, though the file itself is present and directly readable. This asymmetry is inherent to the hub-and-spoke design, not something to fix here.
- **Abandoned or sub-threshold drafts are quarantined, not left live.** See § Failure handling & resume.

The script path is repo-root-relative (unlike the `~/.claude`-absolute helper scripts), so a wrong cwd makes it silently fail to find its target — always run it with the repo root as the working directory:

   ```bash
   cd <mdb-context-hub-root> && node scripts/persist-spoke.mjs <skill-id> [--hub <hub-id>]
   ```

   For each id it: (a) locates the installed source markdown (`~/.claude/skills/<hub>/references/<id>.md`, or standalone `~/.claude/skills/<id>/SKILL.md`); (b) writes the hub-repo backing pair `local-sources/<id>/{context.md, manifest.yaml}` (parsing frontmatter with js-yaml); (c) **idempotently** inserts the `SELECTED_SKILLS` entry at the `// <<< auto-persisted /dr spokes …>>>` marker — **this is the durable registration** (`npm run sync:skills` regenerates `registry.json` from it; anything unpinned is pruned); (d) **best-effort upserts the skill into `skills/registry.json`** so it is **discoverable immediately** via `tam_search_skills`/`tam_get_skill` before the next sync (recoverable — reports but never fails the command); and (e) re-runs `node --check`. 2. **`tam_create_skill` is redundant for `/dr`** — persist-spoke already registers the skill (durable `SELECTED_SKILLS` pin + immediate `registry.json` upsert). Use `tam_create_skill`/`tam_update_skill` only as a fallback if the script is unavailable. Do **not** hand-edit `SELECTED_SKILLS` or `registry.json`.
3. **Batch canonicalize (`concept-family-explorer`):** persist every spoke first, then canonicalize the whole pack once with `node scripts/persist-spoke.mjs <last-id> --hub <hub> --sync` (or `npm run sync:skills`). Per-skill `--sync` is wasteful in a batch (full regen each time).

Run `node ~/.claude/skill-consolidation/referents.mjs --repair` (dry-run first to inspect; add `--apply` once the diff looks right) so every `→ <spoke-id>` and `related_skills:` entry pointing at a folded spoke is rewritten to the hub-aware form. ### Phase 4: Cross-pollination
1. Search existing skills for domain overlap (`tam_search_skills` with topic + each concept). Skip superficial overlap and peers that are read-only or under active development this session.
2. **Peer-write rail** (skill-optimizer Pass O's safety elements by reference; full text: canonical Phase 3): before any edit, snapshot every peer to be edited into `~/.claude/skill-consolidation/backups/dr-crosspoll-<YYYYMMDD-HHMMSS>/` and end the report with the literal restore command. **PAIR check (runtime-derived, never a hardcoded list):** if BOTH `~/.claude/skills/<peer>/SKILL.md` and `~/.claude/skills/<hub>/references/<peer>.md` currently exist (spoke map per the manifests referenced by `~/.claude/skill-consolidation/tiering/tier-config.json`), apply the identical addition to BOTH copies and report both paths — worked example: `deep-research-methods` ↔ `deep-research/references/deep-research-methods.md`. **PROVENANCE check:** a peer dir containing `.skillfish.json` → flag in the report that local additions diverge from its tracked upstream (owner/repo/sha). 3. Update overlapping skills: append relevant findings — **idempotent** (skip if the finding is already present) and bounded to **≤5% of the peer's length per run** (not 30%: a 30%/run cap compounds across repeated runs into peer bloat). Never remove content; if new findings contradict existing peer content, add a "### Conflicts" note rather than overwriting. If a peer would need more than 5%, file it as its own `/dr <peer-topic>` refresh instead of force-fitting it here. After each edit: strict YAML frontmatter re-parse; description still ≤1000 chars; semver-patch + `updated` bump on the peer (per skill-optimizer Step 6.6). 6. **Append telemetry:** one research-run row (`runner: "dr"`) per the canonical telemetry schema (`~/.claude/skill-consolidation/convergence-and-severity.md` §Telemetry — cite, never restate) to `~/.claude/skill-consolidation/research-telemetry.jsonl`; the append is fail-safe — a write error never blocks or fails a run.
7. Report the updated tree structure in the output

### Failure handling & resume
Phases are checkpointed; a partial run must fail safe, not silently:
- Empty invocation (no topic and no `--refresh` id) → prompt the user for a topic; never begin research on an empty string.
- Web search returns no results for a concept → broaden terms / try synonyms for at most 2 rounds, then mark the concept "insufficient data" and move on.
- A topic cannot meet the Authority threshold run-wide (too few credible sources, or purely adversarial with no synthesizable domain) → do NOT install a sub-threshold skill; exit `INSUFFICIENT-AUTHORITY` listing concepts and best sources found, and recommend a narrower scope or `concept-family-explorer`.
- A parallel research agent that fails → record its concept as **blocked** in the report and continue the others; never abort the whole batch for one failure.
- `persist-spoke.mjs` or a hub sync fails → report it explicitly and leave the local skill installed; the run is re-runnable.
- `skill-optimizer` leaves unfixable High findings → surface them instead of installing silently, and **withhold the Phase 3 persist** (`persist withheld: N High findings remain`).
- Hub manifests missing or unparseable → approximate hub matching via `tam_search_skills`/`tam_recommend_skills`, mark every routing decision REGISTRY-UNAVAILABLE (provisional), skip `referents.mjs --repair`, and note that the registry was unavailable.
- Re-running `/dr <topic>` resumes idempotently: the Phase 0 concept-tree and hub checks skip work already completed.
- **Interrupted run:** re-invoking `/dr <topic>` re-resolves the draft path (Phase 0 step 7) and resumes from the draft's own `dr:progress` marker — completed concepts (in `conceptsDone`) are never re-researched; `state:"research-complete"` skips straight to Phase 2. A concept that crashed mid-write is still `conceptsPending` (the marker only advances after its content lands on disk — § Draft file mechanics), but its section heading may already exist on disk with partial content: re-researching it must **replace that stub in place**, not append a second copy of the same heading.
- **Authority threshold not met:** quarantine the draft — move it to `~/.claude/skill-consolidation/backups/dr-drafts/<skill-id>-<timestamp>.md` — rather than leaving a sub-threshold or half-written skill live under `~/.claude/skills`, in addition to the existing `INSUFFICIENT-AUTHORITY` exit.

### Output
Use the structured report format from the prompt: Research Summary (lead with a **Run status:** line — `COMPLETED | BUDGET_EXHAUSTED | VERIFY-DISSENT | persist withheld | INSUFFICIENT-AUTHORITY | REGISTRY-UNAVAILABLE`), Installed Skill details, Skill Audit (skill-optimizer exit state + blind-verification status), Cross-Pollination Results table (with pair-copy paths and per-peer re-sync verdicts, ending with the literal snapshot restore command), Skills Used, Validation Results checklist. Add a **Concept Tree** section showing the updated hierarchy.

### Validation
- Authority threshold: 5+ concepts, 3+ **independent** cited sources each (citation chains collapse to one source — per `deep-research-methods` §Source Evaluation).
- Anti-pattern gate (`deep-research-methods`): ecosystem diversity, disconfirming evidence sought, no unqualified single-source claims, scope held — a failed item means more research, not a caveat.
- **Citation-existence gate:** every `## References` URL appears in THIS run's fetch/search log (zero-fetch bookkeeping check); spot-fetch only URLs absent from the log (e.g., inherited via cross-pollination or cited from search snippets never scraped); plus re-verify 3 sampled anchored claims against their source text.
- Generated skill text passed the injection scan; any quarantined passage is reported with its source URL.
- Skill loads via `tam_search_skills`.
- Skill exists in context hub (tam_get_skill returns the entry).
- Trigger-accuracy eval passes (≥9/10 positive, ≤1/10 negative) and no unresolved collision with a sibling skill.
- `~/.claude/skill-consolidation/evals/<audited-id>.eval.jsonl` exists and was appended this run by skill-optimizer Pass H (the hub's id when the topic was hub-routed, the skill's id when standalone) — show the file path.
- Cross-pollinated skills verified (no data loss) and re-synced (registered/stale/missing verdict per peer).
- Concept tree updated with new entries.
- No leftover draft banner or `dr:progress` comment in the finalized skill/hub reference.
- **Run each check and show its result** — assert with evidence (tool output), do not self-certify.

## Finding skills that would benefit from a /dr refresh

**Do not hand-maintain a static list here.** An earlier version of this section listed specific skills with frozen line counts, and it rotted — most named skills had been consolidated into hubs (the names no longer resolve) and the line counts went stale on the first edit. Compute the candidates at run time instead:

1. **Stale concepts (authoritative):** `tam_concept_tree_list` with `staleOnly: true` — every concept researched >90 days ago. This is the same queue Phase 0 step 4 and Phase 5 step 5 already produce; its consumer is `/dr --refresh`.
2. **Thin / un-sourced skills (optional sweep):** scan `~/.claude/skills` for hub references or standalone skills that are short (e.g. <50 lines) or lack a `## References` / `## Sources` section — those are enrichment candidates.
3. Emit each as a ready-to-run line: `/dr --refresh <concept>   (stale since <date>)` for stale concepts; `/dr <concept>   (reason: thin | no sources)` for enrichment candidates.

This keeps the candidate set live instead of a frozen snapshot that misdirects every run that reads it.
