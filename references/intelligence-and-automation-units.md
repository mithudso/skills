# Intelligence & automation units (v3.0.0)

Detailed execution logic for the 30 v3.0.0 enhancements, extracted from `SKILL.md` for length budget. Each unit runs inside the Agentic execution model's fault boundary: a failure marks its own section `[Section Partial — <reason>]` or `[Section Failed — <reason>]` and never halts the run. Output section names, column schemas, caps, and ordering live in `SKILL.md` § "Markdown structure: context file". Precedence and new sources live in `SKILL.md` § "Precedence when sources disagree" and § "Sources and fallback policy".

## Strategic intelligence (after MongoDB team discovery; feeds Executive summary and maturity)

Depends on: resolved account, `## Cases`, Glean meeting notes, Slack. Runs after Cases + meetings; parallel-safe against Monday/AHA/Tableau. Precedence: SFDC > Drive canonical > MongoDB team docs > meeting notes > Slack/Email. Dedupe every extracted entity (competitor, exec name) case-insensitively before scoring.

1. **Competitive intelligence (1.1).** Scan meeting notes, Slack, case comments, and SFDC opportunity competitor fields (`Opportunity.Competitor__c` or the account competitor picklist) for AWS DocumentDB, Azure Cosmos DB, DynamoDB, Cassandra, Couchbase, and other named competitors. Per mention capture: competitor, date, source link, context tag (`win`|`loss`|`feature`|`pricing`), sentiment toward MongoDB. Dedupe on competitor; keep newest as `Last Mentioned`; derive `Key themes` (won-on vs at-risk). Fallback: SFDC competitor field absent → meeting/Slack/case mentions only, `[Section Partial — SFDC competitor field unavailable]`; no mentions → `None identified this run` (not a failure).
2. **Renewal risk scoring (1.2).** Compute score 0–100 from signals gathered elsewhere this run: downward sentiment trend **+20**; each open Sev-1/Sev-2 **+10**; each unanswered question open >7d **+5**; meeting-cadence decline >30% QoQ **+15**; feature-request rejection rate >50% (AHA `Declined`/`Won't Fix` over total) **+10**; "evaluating alternatives" language **+25**; budget-concern mentions **+15**; contract expiry <90d **+10**. Cap 100. Bands: 0–25 Low · 26–50 Medium · 51–75 High · 76–100 Critical. Fold as a single line into `## Executive summary`; never a standalone section. Fallback: any input unavailable → compute from available signals, append `(partial — missing: <inputs>)`; never block the summary.
3. **Expansion/upsell opportunity detector (1.3).** Scan meetings, Slack, cases, Drive for growth signals: new workload, region expansion, scale-limit comments, new team on MongoDB, self-hosted→Atlas candidacy, licensed-but-unused features. Per signal capture: description, type, estimated value (or qualitative), timeline, status (`identified`|`discussed`|`blocked`), blocker. Cross-reference AHA/Monday to avoid duplicating a tracked initiative. Fallback: none found → `None identified this run`; source outage → `[Section Partial — <source> unavailable]`.
4. **Executive stakeholder map (1.4).** Extract VP+/C-suite from SFDC `Contact.Title`, Glean meeting attendees, email signatures. Per exec capture: name, title, last touchpoint + source, last-3 topics, sentiment, engagement trend (`increasing`|`stable`|`decreasing` from touchpoint frequency over the last two quarters), notes. Derive reporting chain where stated. Flag risks (no VP+ sponsor; champion with no touchpoint in window) and strengths (≥2 execs trending stable/increasing). Fallback: `[Section Partial — SFDC contact titles unavailable]` (meeting/signature parsing only).
5. **Customer maturity model (1.5, final strategic unit; deps cases + meetings + prior context).** Score 1–5 across MongoDB expertise, observability, DR readiness, security hardening, operational excellence. Evidence: case-type ratio (reactive→1, proactive→5), architecture docs, runbook existence, meeting content (DR test, security review). Compare each dimension to the prior context file for `Trend vs Prior Quarter` (`up`|`down`|`flat`|`new`). Compute Overall maturity + recommended focus (lowest or down-trending dimension). Fallback: no prior file → all `new`; insufficient evidence for a dimension → `Score —` with `Evidence: insufficient data` (never guess).

## Technical intelligence (after Tableau and contract/SFDC analysis)

Derives technical/operational facts from architecture docs, case history, Tableau, and SFDC contract data. Each sub-block is independent. Precedence: Tableau canonical for quantitative facts; SFDC contract attachments canonical for commitment terms.

1. **Technology stack inventory (2.1).** Scan architecture docs, case comments, meetings, SFDC custom fields (`Account.Tech_Stack__c`) for languages, frameworks, cloud, non-MongoDB databases, CI/CD, monitoring/APM. Categorize; capture version or `[version unknown]`. Flag integration opportunities where a detected tech has a MongoDB path (Kafka→Atlas Triggers/Connector, Spark→Spark Connector, Terraform→Atlas provider). Fallback: `[Section Partial — architecture docs and SFDC custom fields both unavailable]`.
2. **Migration status timeline (2.2, CONDITIONAL).** Run only if a migration signal is present ("migrating to/from MongoDB", "lift-and-shift", "strangler fig", explicit migration project); if none, omit the section (not a failure). Capture type, source/target, stages, planned go-live, rollback-plan existence, actual-vs-planned per stage (Δ). Any migration **away from MongoDB** = high-priority early warning with captured reasons cited to source. Fallback: `[Section Partial — migration detected but stage dates unconfirmed]`.
3. **Performance & scale trends (2.3, deps Tableau + Cases).** Extract cluster count, data volume, peak QPS, Atlas spend, avg connections from Tableau (canonical), cases, meetings, SFDC custom fields. Compute QoQ and YoY growth. Flag any metric with **>50% change** QoQ or YoY without a sourced explanation as `[Anomaly — unexplained]`. Fallback: `[Section Partial — Tableau dashboard unavailable; SFDC/case figures only]`.
4. **Anti-pattern recurrence tracker (2.4, after Tableau; deps Tableau + Cases).** Cross-reference the Tableau `Anti-Patterns` dashboard against case history for the same Org/Project ID; group by type. **Recurrence** = same type >1x in a rolling 180-day window. Map: single→monitor; recurrence→`training`|`architecture review`|`runbook` by pattern class. High-priority callout for ≥3x-in-180d or Sev-1/Sev-2-linked. Fallback: `[Section Partial — Tableau anti-pattern feed unavailable; case-only recurrence, unverified]`.
5. **SLA/SLO commitments registry (2.5, after contract analysis; deps SFDC contract data).** Extract response-time SLAs, uptime SLOs, escalation triggers, resolution timeframes from SFDC contract attachments (canonical for terms), meeting notes ("we committed to X"), case comments. Track commitment / actual performance / status (`met`|`at-risk`|`breached`). Fallback: `[Section Partial — contract attachments inaccessible; meeting-note commitments only, unverified against contract]`.

## Relationship intelligence (after Sentiment sweep, before Unified TODO compilation)

Draws on cases, Glean meeting notes, and Slack (post-Slack intervention audit). Hallucination guard (reuse the Slack-audit rule): never fabricate a quote, date, or attribution without a direct source link; omit rather than guess.

1. **Communication velocity heatmap (3.1).** From case-comment and email timestamps, compute avg response time per direction (MongoDB→Customer, Customer→MongoDB) over the window. Flag `Going dark`: no contact either direction for **>14 days** on an open case/active initiative. Flag `Asymmetric urgency`: customer sends ≥2 messages with no reply while MongoDB's avg reply lag on the thread exceeds **>48hr**. Trend (`improving`|`stable`|`degrading`) vs prior window. Fallback: `[Section Partial — case/email timestamps unavailable]`.
2. **Unacknowledged value delivered (3.2, deps cases).** Extract MongoDB wins from case resolutions (prioritize Sev-1/Sev-2), meeting notes, perf improvements. Quantify impact when sourced. Flag `Customer acknowledgment: absent` when no customer-side reference to the win within 30 days of resolution. Build one QBR story line per win. Fallback: `[Section Partial — no case resolutions in window]`.
3. **Broken promises / commitment tracker (3.3, deps meetings + cases).** Extract commitment phrases ("will follow up by", "will deliver", "by <date>", "targeting <date>"). Status: `Kept` (delivered on/before due), `Overdue` (past due ≤7d), `Broken` (**>7 days** overdue, no delivery). Auto-flag crossing 7 days as `Broken`. Promise-keeping rate = Kept / (Kept+Overdue+Broken). Never infer an unstated due date — list with Due `—` and exclude from the rate. Fallback: `[Section Partial — no explicit commitments found]`.
4. **Meeting participant pattern analysis (3.4, deps meetings + sentiment).** Over the last 6 customer-facing meetings, per attendee capture role, present/absent per meeting, trend (`consistent`|`dropping off`|`newly joined`|`role change`). Flag `Exec stopped attending` (exec present in ≥2 of first 3, absent from last 2) and `New attendee` (only in the most recent). Suggest one relationship action per flag. When a Glean meeting note lacks an explicit attendee list, run Glean `search` for that meeting's calendar entry (invitee list) before treating attendance as unknown; tag any attendee resolved this way `Source: Glean (fallback)` per `## Sources and fallback policy` item 4. Fallback: `[Section Partial — meeting attendee data unavailable]` only when both meeting notes and calendar lookup fail.
5. **Customer champions & detractors (3.5, deps meetings + sentiment).** Per-person (not per-account): **Champions** = ≥2 independent positive-signal sources; **Skeptics** = ≥2 independent negative-signal sources; **Neutrals** = no clear signal or one weak signal. Track sentiment trajectory across the last 2 windows where evidence supports it. Fallback: `[Section Partial — insufficient per-person sentiment evidence]`.

## Knowledge capture (after Case analysis; consumes Technical + Strategic intelligence)

Isolated unit; sub-blocks run independently. 4.4 consumes 2.4 + 1.5; 4.5 consumes SFDC contract/tier. Use `[Section Partial — <reason>]` (partial table still emits); reserve `[Section Failed]` for total retrieval failure of the unit.

1. **Reusable solutions library (4.1, deps cases).** For each `## Cases` row with `Status = Closed` + captured `Resolution`: extract problem type (taxonomy: index/schema/query-perf/replication/sharding/driver/migration/cost/security), root cause, solution summary, quoted runbook/code snippet. Tag category, scope (`customer-specific`|`general`), reusability (`High`|`Medium`|`Low`). Flag vector-similarity auto-suggestion eligibility (pointer only; no embedding at generation time). Fallback: `[Section Partial — no closed cases with captured resolution]`.
2. **Customer-specific gotchas (4.2).** Scan meetings, case comments, runbooks for unusual constraints: policy restrictions (change-freeze, approval chains), approval requirements, unusual architecture choices (with stated reason). Record first- and last-mentioned dates. Flag `[Repeatedly forgotten]` when the same constraint is independently raised **>2x** in the window (a team-runbook gap, not customer behavior). Fallback: `[Section Partial — no constraint language found in retrieved sources]`.
3. **Knowledge decay detector (4.3, deps Corpus manifest + Drive metadata).** For each `## Corpus manifest` document pull Drive last-accessed and last-modified. Flag `Stale — not accessed` when last-accessed >**180 days**; `Stale — not modified` when last-modified >**365 days**. Tribal knowledge = a topic in ≥2 meeting notes with no matching corpus document. Recommend `Refresh`|`Archive`|`Convert to runbook` / `Document it`. Fallback: Drive access-date metadata unavailable → skip the not-accessed check, `[Section Partial — Drive access-date metadata unavailable; not-modified check only]`.
4. **Training needs assessment (4.4, deps cases + 2.4 + 1.5).** A gap qualifies when a case type recurs (same category in ≥3 cases in window), an anti-pattern from 2.4 shows in ≥2 Tableau sweeps, or the 1.5 maturity score for that competency is low. Map to a training offering (index design, aggregation, schema design, Atlas Search, vector search). Estimate case-reduction impact (`High`|`Medium`|`Low`) by recurrence; track `Delivered` (Y/N + date from Monday/Glean) and `Outcome` (post-training recurrence trend). Fallback: `[Section Partial — <missing input>: 2.4 unavailable | 1.5 unavailable | insufficient case volume]`.
5. **MongoDB feature adoption tracker (4.5, deps architecture docs + contract/tier).** Pull available Atlas features from SFDC tier field / Atlas org plan; cross-reference actual use evidenced in Tableau + architecture docs (Search/Vector Search index presence, Online Archive config). Adoption per feature (`In use` / `Available, not in use`). Flag underutilized (available, unused, no stated reason) and suggest enablement. Fallback: `[Section Partial — tier/contract not resolved from SFDC]`.

## Workflow automation (final unit; deps: all analysis complete)

Same fault-boundary and idempotence rules as other units — a failure marks `[Section Failed — <reason>]` or `[Automation disabled — <tool>]` and never halts the run. Reuses hallucination guards from `## Monday.com bidirectional sync` / `## Slack intervention audit`: never push AI-generated content without a human-authored fence/marker; never fabricate a value, quote, or confidence score. Each automation runs at most once per trigger firing (one-attempt-per-run, matching the `/dr` cap; no in-run retries). None of the five is a hard precondition, so none can halt the run.

1. **Automated case pre-analysis (5.1) — customer-facing (case comment), internal status block.** Trigger: new-case webhook, or polling fallback. Steps: semantic search on subject+description against the resolved-case vector corpus → pull relevant context/runbook/architecture docs by keyword → generate suggested troubleshooting steps → post an "AI Pre-Analysis" case comment with a confidence score (always attached; comment is additive, never edits existing content). Preconditions: case-corpus vector DB + context-file access. Fallback: `[Automation disabled — vector DB unavailable]` / `[Automation disabled — context file unavailable]`. Status + recent pre-analyses emit to `## Workflow automations`.
2. **Meeting prep assistant (5.2) — EPHEMERAL, not written to the context file.** Trigger: calendar detection, fired 24h before a customer meeting. Steps: pull last-30-day cases, open TODOs, sentiment trend, last unresolved question → generate a talking-points brief → deliver via Slack DM/email/append. Preconditions: calendar access + a delivery channel. Fallback: `[Automation disabled — calendar access unavailable]`; if the brief generates but no channel exists, hold and log (never silently drop). Single-use; not persisted as a corpus document.
3. **Stale TODO auto-nag (5.3) — extends `## Unified TODO compilation` / `## TODO`.** Trigger: daily cron scanning `## TODO` for owner + due date. Thresholds: age ≥7d → Slack DM owner; ≥14d → owner + CC manager; ≥21d → escalate to director. Mark each row nagged at that tier so it is not re-sent at the same tier (idempotent per tier; only a new threshold crossing fires again). Preconditions: Slack API + resolvable owner/manager/director identity. Fallback: `[Automation disabled — Slack unavailable]`; per-row `Nag failed — owner unresolved` on identity failure (does not fail the unit).
4. **Context drift detector (5.4) — new section `## Context drift analysis`.** Trigger: monthly cron. Steps: load the current context file plus 30/60/90-day-prior files → diff sentiment, case volume, blocker themes, exec engagement, competitive-threat signals → flag any dimension with Δ **>20%** or a categorical shift → emit the monthly delta report. Precondition: ≥1 prior context file at/before the 30-day mark (no history yet is not a failure). Fallback: `[Automation disabled — context-file history unavailable]` / `[Section Failed — insufficient context-file history]` for a single run.
5. **Intelligent case routing (5.5) — EPHEMERAL, not written to the context file.** Trigger: new-case webhook (separate step from 5.1). Steps: analyze subject/description/history → suggest an owner via past-similar-case resolver + customer rapport + current workload + skill match → pre-populate context snippets, similar-case links, runbook links for the case-assignment UI → attach a confidence score. Preconditions: vector DB + workload/skill data + case-assignment UI integration. Fallback: `[Automation disabled — vector DB unavailable]` / `[Automation disabled — case-assignment UI integration unavailable]`. A suggestion, never an auto-assignment; a human makes the call.

## Presentation generation (last unit; dep: full context file assembled and merged)

All items are rendering transforms over already-built content — never a new retrieval. On any sub-failure emit `[Section Failed — <reason>]` in that slot and continue.

1. **Summary variants (6.1).** From the assembled `## Executive summary`, generate three audience-tuned versions and prepend them: `30-second` (50–75 words: status + single top risk/opportunity; exec), `2-minute` (200–300 words: status, sentiment trend, top 3 items; technical), `5-minute` (the existing ≤ 250-word summary, unchanged; new-TAM/handoff). Word budgets are hard; trim lowest-signal first. Never introduce a fact absent from the full summary.
2. **Visual timeline (6.2).** Convert `## Chronology` events into one Mermaid `gantt` block (cases, milestones, sentiment-trend shifts, team changes, incidents; color-coded via `:crit`/`:active`/`:done` + section grouping). Emit as `## Visual timeline` directly after `## Chronology`. No event not already in `## Chronology`.
3. **Q&A indexing (6.3).** Precondition: a reachable vector store. Chunk the emitted context file by `##` section, embed, register under `ctx-<CUSTOMER_SLUG>`; expose semantic search + cited Q&A via MCP tool `query_customer_context(question, account_id)`. Emit status to `## Context Q&A capability`. Fallback: `[Automation disabled — vector store unavailable]`.
4. **Accessibility sidecar (6.5).** Generate `context-v3-accessible.md` (per `## Markdown structure: accessibility sidecar`) from the same assembled content. Emit fresh each run. Fallback: `[Section Failed — accessibility sidecar not generated]`; the dated context file is unaffected.
