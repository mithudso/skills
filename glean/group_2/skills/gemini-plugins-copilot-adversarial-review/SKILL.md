# Copilot Adversarial Review

Two-pass adversarial review of recent code changes using GitHub Copilot CLI. Intentionally uses a different frontier model family (GPT) and a different execution harness than the current session to maximize independence of the second opinion. Produces a synthesized, judgment-filtered report — not raw Copilot output.

## Prerequisite

`copilot --version` must succeed. Requires GitHub Copilot CLI with GPT model access.

## What to Skip

Skip the review entirely if the target file is:
- Auto-generated (contains `DO NOT EDIT`, `generated by`, or is a protobuf stub)
- A BUILD or Bazel file

All other file types are in scope: source code, JSON, YAML, and markdown.

## Step 0: Detect Latest GPT Model

```bash
LATEST_GPT=$(copilot -p "What is the single most capable base GPT model ID available to you right now? Reply with only the model ID (e.g. gpt-5.4), nothing else." --silent \
  | grep -oE 'gpt-[0-9]+\.[0-9]+' | head -1)
[[ "$LATEST_GPT" =~ ^gpt-[0-9] ]] || LATEST_GPT="gpt-4.1"
```

Use `$LATEST_GPT` as the `--model` value in Steps 1 and 2.

## Step 1: Adversarial Review Pass

Run against the files passed as arguments (defaults to most recent changes if empty):

```bash
copilot -p "Adversarially review the most recent changes to $ARGUMENTS. Find bugs, security issues, data loss risks, missing error handling, race conditions, and unhandled edge cases. For each issue, suggest a concrete safer or more readable alternative with actual code. Skip style-only feedback. If the code is clean, say so in one sentence." \
  --model "$LATEST_GPT" \
  --allow-tool='shell(git)' \
  --silent
```

## Step 2: Missing Test Cases Pass

```bash
copilot -p "Review the most recent changes to $ARGUMENTS for missing test cases. List only tests that would catch real bugs — not exhaustive coverage for its own sake. For each, name the scenario and why it matters." \
  --model "$LATEST_GPT" \
  --allow-tool='shell(git)' \
  --silent
```

## Step 3: Synthesize with Judgment

Read both outputs and apply your own judgment:

- For each finding: is it a real risk, or a false positive given the codebase context?
- For each alternative: is it genuinely better (safer, more readable, more performant)? If yes, apply the change.
- For each test gap: would this test actually catch a real bug? If yes, note it as a genuine gap.

## Step 4: Return Synthesis

Return a concise summary — not raw Copilot output. One line per finding:

```
**Adversarial review — `<filename>`**
- [issue or alternative]: [your assessment — material / immaterial / accepted]
- No material issues found.  ← if clean

**Test coverage**
- [gap]: [your assessment]
- No gaps found.  ← if clean
```

## Example Output

```
**Adversarial review — `UserService.java`**
- Missing null check before `processUser()` call on line 45: material — added Optional guard
- Unused import on line 3: immaterial (style only, skipped)

**Test coverage**
- No test for the null-user path added in processUser(): genuine gap
```
